# 03 UI/UX 設計

## 1. 6つのユーザーフロー

（操作数 = タップ・入力の回数。情報量 = 判断に使う画面上の要素の数。いずれも設計上の値で、実測ではない）

| # | フロー | 手順 | 操作数 | 意思決定 | 誤操作の可能性と対策 |
|---|---|---|---|---|---|
| 1 | 初回起動→最初の学習 | 開く →「学習を始める」→（学習）→「学習を終える」→ 時間確認 → しおりを挟む（任意）→ 保存 | 3〜4 | 「始めるかどうか」だけ | 未設定でも開始可。プラン作成は強制しない（ホームの空欄「きっかけを決める」から任意で） |
| 2 | 通常の開始 | 開く → プランの文（もし〜なら → この一手）を見る →「この一手を始める」 | **1** | なし（事前に決めてある） | 開始後に「ホームに戻る」で計測は続く。二重開始なし |
| 3 | 時間がない日 | 開く →「小さく始める」（自分で決めた一手・分数）→ 時間になったら続けるか終えるか | 1 | 「通常か小さくか」の二択 | 延長は任意（目標を通常に伸ばすボタン）。自動で完了・記録しない |
| 4 | 終えてしおりを保存 | 「学習を終える」→ 時間（必要なら修正）→ しおり（候補ボタン：続き／解き直し）→ きっかけ通りか（任意1タップ）→ 保存 | 2〜4 | 次の一手の内容 | 1分未満は切り上げない。保存失敗時は入力保持。二重保存なし |
| 5 | 数日ぶりの再開 | 開く →「また、ここから。」→ しおりから／小さな一手で／プランを1つ変える | 1 | 3択 | 空白日数・失敗・ストリークを表示しない。表示ルール：最後の実記録から2日以上 |
| 6 | できなかった条件を見直す | ホームの「週の見直し」→ 7日間の事実 → 1つ選ぶ（任意で始めやすさ1〜5）→ 保存 → 該当欄にフォーカスしたプラン画面 | 3〜4 | 「何を1つ変えるか」 | 選ばずに保存できない（エラーで案内）。「今週はしない」で7日間出さない。オフにできる |

### 画面の切り替えルール（ホーム）
1. 進行中の計測があれば →「学習中の画面に戻る」だけを表示
2. 設定が「記録中心」なら → 簡素なホーム（比較用）
3. 最後の実記録から `RESUME_GAP_DAYS`（=2）日以上 → 再開画面
4. それ以外 → プランの文（もし〜なら → この一手 → できない日）
5. 週の見直しは、記録が1件以上あり、初回利用または前回の見直しから7日以上、かつ「今週はしない」から7日以上で表示（再開画面にも表示）

## 2. 3つのデザイン方向性の比較

画像：`design/mockups/A.png`、`B.png`、`C.png`（同じ内容・同じ3画面：ホーム、プラン設定、再開）

| 評価軸（10点、主観評価） | A Minimal & Editorial「しおりの一文」 | B Functional & Interactive「今日の流れ」 | C Warm & Human-centered「やさしい会話」 |
|---|---:|---:|---:|
| 視覚的完成度 | 8 | 7 | 7 |
| 情報階層 | **9** | 6（統計・時間選択・手順が同じ重み） | 7 |
| 行動開始の明確さ | **9**（主ボタン1つ） | 6（時間選択→スライドの2操作） | 8 |
| 操作性 | 8 | 6（スライド開始はキーボード・支援技術で不利） | 8 |
| 日本語の読みやすさ | **9** | 7 | 8 |
| 独自性 | **9**（if-then を文と糸で見せる） | 6（一般的なダッシュボード） | 6（チャット UI は AI ボットに見える） |
| 長期利用の快適さ | **9** | 6（毎日の統計は比較・圧力になりうる） | 5（毎回の声かけは飽き・過剰な励まし） |
| アクセシビリティ | 8 | 6 | 8 |
| 実装可能性 | **9** | 7 | 8 |
| 画面間の一貫性 | 8 | 8 | 7 |

**選定：A を基本に、B の「例のチップ（選ぶだけ）」と C の「再開時の一つずつ並んだ選択肢」を採用。**
判断理由は見た目よりも**行動開始のしやすさ**：A だけが「開く→自分の if-then を読む→1タップ」で、開始前の判断を増やさない。B は時間の選択と統計が開始前の判断を増やし、C は会話形式が毎回の励まし文になりやすい。

### 初稿（A）の問題点と修正
| 初稿の問題 | 修正 |
|---|---|
| プラン設定の「文の中の空欄に直接入力」は、スクリーンリーダー・スマホ入力で扱いにくい | 入力欄は通常のラベル付きフォームにし、上に**文のプレビュー**を置く（入力に追従） |
| しおりの候補が「〜3問解くの続き」と不自然な日本語になる | 「続き：〜」「解き直し：〜」の形式に |
| 再開画面にしおりが2回出る（選択肢の説明と下部） | 下部の重複を削除 |
| 「2分だけ（2分）」の重複表記 | 未設定時は分数を省略 |
| 小さな一手で始めた後、しおりが消える | 小さな一手の後は**しおりをそのまま残す**（未完了の一手のため） |
| 週の見直しの事実が奇数個で空きマスができる | 最後の項目を全幅に |
| 曜日チップが 390px で2段に折り返す | 7列グリッドに |
| PC で利用開始前の日を「予定の日のうち0日」と数えていた | **利用開始日以降の予定日だけ**を数える |
| 再開画面では週の見直しが出なかった | 再開画面にも表示 |
| 一時停止中のタイマー数字が半透明でコントラスト不足 | 色で弱める（4.67:1） |

最終UI：`docs/redesign/final-ui-mobile.png`（初回／通常／学習中／しおり保存直後／再開）、`docs/screenshots/`（スマホ・PC 全画面）

## 3. デザインシステム

- **色**：既存トークン（canvas #F7F7F4、ink #142B45、muted #627180、accent #427C67、accentText #356B58、accentSoft #EDF3EF、border #E4E8E6、dangerText #9E4B48）＋ 非テキスト3:1用の control-border #87949E、track #DCE6E0。
- **糸（thread）**：きっかけ→一手の関係を示す唯一の装飾。白抜きの点＝条件（もし）、塗りの点＝行動（この一手）。他の画面では使わない。
- **文字**：Noto Sans JP 系。一手（しおり）28px/800（PC 36px）が画面で最も大きい文字＝最重要情報。数字は tabular-nums。
- **ボタン**：主＝紺（画面に1つ）、副＝薄緑、補助＝下線リンク。角丸は主ボタン・入力 12–13px、チップは全丸、事実の表のみ 14px（すべてに同じ角丸を使わない）。
- **チップ**：例・候補の「選ぶだけ」入力。`aria-pressed` で状態を伝える。
- **事実の表示**：週の見直し・PC の補助欄だけ。良し悪しの色分けはしない（中立）。
- **モーション**：しおり保存直後の一手のフェードイン（0.6s）とトーストのみ。`prefers-reduced-motion` で無効。

## 4. 状態遷移

```
ホーム: active? → 学習中バナー
        simple? → 記録中心ホーム
        最終実記録から≥2日 → 再開（3択 ＋ 週の見直し）
        それ以外 → プランの文（＋ 週の見直し）
セッション: (なし) --この一手/学習を始める--> running(standard, fromBookmark=しおり有)
            (なし) --小さく始める--> running(small, 本人の小さな一手 or 2分)
            running ⇄ paused、→ completing（戻ると completing 中は一時停止扱い）
            completing --保存--> 記録 + しおり更新（small のときは既存しおりを初期値に）
週の見直し: due → 保存（change, ease?, note?）→ change≠none ならプラン画面の該当欄へ
            due → 今週はしない → 7日間非表示
```

## 5. データ（記録・計画・行動・推定の区別）
| 種類 | 保存場所 | 例 |
|---|---|---|
| 確認済みの実績（基準値） | コード定数 | 1,056分（2026-10-07まで） |
| 記録（本人が確認した学習） | records | 日付・分数・内容・メモ |
| 計画 | settings | きっかけ、しおり、小さな一手、予定の曜日 |
| 行動の事実（自動・推定なし） | records の追加項目 | しおりから始めたか、小さな一手か、開いてから開始までの秒数、予定日か、しおりを残したか |
| 本人の回答（任意） | records / reviews | きっかけ通りか、始めやすさ1〜5、見直しで変えたこと |
| 推定値 | **保存しない** | — |
